## Hallazgo de entorno (sin acción de código)

`npm ci` en el contenedor de esta sesión no instaló el binario opcional
`@next/swc-linux-x64-gnu` (necesario para que Turbopack corra en Linux glibc x64) — solo se
instaló `@next/swc-linux-x64-musl`, que no puede cargar en este Ubuntu 24.04 (glibc):
`libc.musl-x86_64.so.1: cannot open shared object file`. Consecuencia: `npm run build` falló con
"Turbopack is not supported on this platform... Only WebAssembly (WASM) bindings were loaded".

Diagnóstico: no es un bug de este repo — `package-lock.json` lista `@next/swc-linux-x64-gnu@16.2.11`
como dependencia opcional válida para `os:linux`/`cpu:x64` sin restricción de `libc`. Es una
resolución incorrecta de `npm ci` específica de este contenedor — sin precedente en los 63 ticks
previos, todos con `build ✅`.

Workaround aplicado y verificado: `npm install @next/swc-linux-x64-gnu@16.2.11 --no-save` — el
build pasó de inmediato, sin ningún cambio de código. Documentado en `CLAUDE.md` § Ancla de
rollback para que, si reaparece en un tick futuro (contenedor nuevo por disparo), el diagnóstico
sea inmediato. No se abre un Error Conocido formal: no hay fix de repo posible y no hay evidencia
aún de que sea recurrente.
